    API reference¶

    The classes and methods scripts use most. For how they fit together, see Behaviours and Gameplay recipes.

    SceneScript setup, find, find_all, find! (see Setting a level up in Ruby)
    Scene.spawn Scene.spawn("Bullet", position: v, rotation: euler, physics: true) copies a prefab = true template (hidden and inert in the game) with its physics and scripts; copies of animated characters move like the original
    Scatter Scatter.place("GrassTuft", count: 50_000, area: [corner, corner], ground: Scene.find("Ground"), seed: 7, scale: 0.7..1.4, align: true) puts copies of an object's mesh (its scale, tint, drawing distances and cast_shadow too) in great numbers: only drawn, never objects of their own, the same places for the same seed on every machine. Each stands where a ray straight down meets ground (none where it misses it); without ground, on the area's bottom. align: true leans them with the slope. How they look: tints: [[r, g, b], ...] (each copy a color along the list), tint_variation: 0.1 (brighter or darker by up to that share), fade: 8.0 (meters over which they fade out before the template's visible_to instead of popping), normals_up: 0.7 (grass lit as the ground it stands on). Returns a set: count (how many were placed), remove; Scatter.clear removes them all. A scene holds at most 262,144 (see Levels)
    Particles Particles.burst(position, count:, color:, alpha:, glow:, lit:, soft:, direction:, spread:, speed:, life:, size:, gravity:, image:, frames: [columns, rows], fps:, spin:) → how many were added (size, color and alpha may be lists of up to 4 values over the particles' life: see Gameplay recipes), Particles.count, Particles.clear

    Audio Audio.play(:jump, volume:, pitch:), Audio.music(:theme, loop: true, volume: 0.7), Audio.stop_music, Audio.music_pitch = 1.2, Audio.music_volume = 0.5 (change them every frame for an engine's drone), Audio.volume = 0.8 (files in sounds/)

    I18n I18n.t("hud.coins", count: 3) → the text of a key in the language in use, its {count} filled (see Texts in several languages), I18n.locale (:en), I18n.locale = :pt, I18n.available_locales (the languages of the game's locales/ files)
    Vector3 Vector3.new(x, y, z), Vector3.zero, one, up, down, left, right, forward, back; arithmetic, dot, cross, length, normalized, clamped(max_length = 1.0), lerp, flat, with(y: 0), distance_to, approx?, to_a; in place, for math done thousands of times a frame: set(x, y, z), add!(v), sub!(v), scale!(k), normalize! (they change the vector and hand it back: dup one you got from someone else first)

    Script errors are logged with a backtrace and only disable the failing behaviour; the game keeps running. Every native takes finite numbers a float can hold: infinity, NaN (0.0 / 0.0) or a number too large (1e300) raises an ArgumentError instead of reaching the scene. So does Vector3 arithmetic whose result would leave that range, and dividing a Vector3 by zero; a vector changed in place (add!, scale!...) is left as it was when that happens. A setting with a range raises outside it and says the range (Camera.motion_blur must be from 0 to 1, not 3); nothing is quietly clamped, except Vehicle#drive's inputs, which an analog stick may push a little past full. Assigning transform.position to a physics object teleports it (moving bodies also stop); changing its rotation keeps its velocity. Vehicle wheel meshes must have their rotation applied (axle along X).
