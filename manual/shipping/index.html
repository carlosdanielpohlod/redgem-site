    Building and sharing¶

    Build in the editor's toolbar, or from a terminal:

    ./build/src/redgem build my_game dist/my_game

    This makes a folder with an executable named after your game (dist/my_game/my_game) and a game/ folder with its files. Whoever receives the folder runs the executable: they do not need RedGem, Ruby or Blender installed.

    That executable is the player: a copy of redgem-player, a small program that plays the game in the game/ folder beside it and does nothing else. The editor, the project hub and the other tools you make the game with are not in it. A build looks for the player beside the redgem program that builds: redgem-player in the same folder for the system you are on, and runtimes/<system>/ in that folder for the others (runtimes/windows/redgem-player.exe, runtimes/android/<abi>/libredgem.so). When one is missing the build says which file it looked for.

    For Windows¶

    On Linux, RedGem builds games for Linux, Windows and Android (the experimental Windows download builds Windows games). In the editor, Build asks which one; from a terminal:

    tools/windows/build_runtime.sh                                   # once: builds the player for Windows
./build/src/redgem build my_game dist/my_game_win --target windows

    The first command downloads a Windows compiler into the project (no administrator rights needed) and builds redgem-player.exe into build/src/runtimes/windows/; it takes a few minutes and is only needed once, or again after updating RedGem. The build then makes dist/my_game_win/my_game.exe next to its game/ folder. It needs 64-bit Windows 10 or later and a graphics card with OpenGL 3.3; nothing has to be installed with it.

    For Android¶

    tools/android/build_runtime.sh                                   # once: builds the player for Android
./build/src/redgem build my_game dist/my_game_android --target android

    The result is dist/my_game_android/my_game.apk, with the game's files inside it. Install it on a phone with adb install, or copy the file to the phone and open it. tools/android/run_on_device.sh my_game builds, installs, starts the game on the phone or emulator that adb sees, and shows its log.

    What it needs on your machine:

    • The Android SDK with its build-tools and one platform (sdkmanager "build-tools;35.0.0" "platforms;android-35"), and ANDROID_HOME pointing at it.
    • Java (the SDK's signing tool runs on it).
    • The first command downloads the Android compiler (NDK) into the project and builds the engine for phones (arm64) and for emulators (x86_64); it takes several minutes, once.

    What changes on a phone:

    • The game fills the screen: it keeps the height from game.json and gets the width that fits.
    • Touch controls appear by themselves and act as a gamepad: a stick under the left thumb, A and B under the right, Start in the corner. A game that plays with a gamepad plays on a phone as it is; taps also work as mouse clicks, so UI.button menus work. A game with a touch interface of its own hides them with Input.touch_controls = false.
    • Characters may have up to 48 bones on a phone (64 on a computer).
    • There is no on-screen keyboard yet, so text fields cannot be typed in.
    • Phones are slower than computers: keep levels light (few lights, modest textures) and test on a real device. It needs Android 8 or later with OpenGL ES 3.
    • The APK is signed with a key the engine makes on your machine the first time (~/.config/redgem/android-debug.keystore). It never leaves your machine and is different on everyone's; it is good for your own devices and for sharing the file.

    Your own app id, version and key¶

    A game says these in the android section of its game.json; all are optional:

    {
  "title": "My Game",
  "android": {
    "package": "com.mystudio.mygame",
    "version_code": 3,
    "version_name": "1.2",
    "keystore": "../keys/release.keystore",
    "key_alias": "mygame"
  }
}
    • package is the app's id on the phone. Without it the app goes by the game's id (see below), and a game with no id by its folder name.
    • version_code goes up with every release: a phone only updates to a higher one.
    • keystore and key_alias sign the app with a key of your own, which is what a release needs: players can only update a game signed with the same key as the one they have. Make it once with Java's keytool and keep it safe (and backed up): there is no getting it back.
    • The key's password is never written in a file. Give it when building:
    REDGEM_KEYSTORE_PASSWORD='...' ./build/src/redgem build my_game dist/android --target android

    (REDGEM_KEY_PASSWORD too, when the key has a password of its own.) - Keep the keystore outside the game's folder. If one is left there anyway, builds leave it out: a signing key never travels with a game.

    Notes¶

    • The executable needs the game/ folder next to it.
    • game.json says what the game is and how its window opens:
    { "id": "com.mystudio.mygame", "title": "My Game", "window_width": 1280, "window_height": 720 }

    • id is what the game is known by: its save follows it when the folder is moved or renamed, and its Android app is named after it. redgem new writes one (my-game-3fa2c1b0); change it to your own before the first release and leave it alone after. It is small letters, digits, ., - and _, starting and ending with a letter or a digit. Two games with the same id share a save: a game started as a copy of another needs a new one. A game with no id keeps its save by where its folder is, and starts a new save when it is given one.

    • Everything in the game folder is copied, including the scripts as plain .rb files.

    • Check the licenses of the models and sounds you include. A license that allows using an asset in a game does not always allow shipping its original file.

    Installing RedGem somewhere else¶

    cmake --install build --component redgem --prefix <folder> copies the programs out of the build folder, laid out the way builds expect:

    <folder>/bin/redgem            the editor, the project hub and the command line
<folder>/bin/redgem-player     what a game built for this system is a copy of
<folder>/bin/redgem-relay      the meeting point for games over the internet
<folder>/bin/redgem-test       the tool that runs a game's tests
<folder>/bin/runtimes/         the players for other systems that were built before installing
